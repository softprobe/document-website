# 架构

深入了解 SP-Istio Agent 的工作原理。

## 概述

SP-Istio Agent 是一个高性能的 WebAssembly (WASM) 插件，在 Envoy 代理（Istio sidecar）内部运行，用于在业务层面捕获和分析 HTTP 流量。

## 技术栈

- **Rust** - 内存安全、高性能的系统编程语言
- **WebAssembly (WASM)** - 可移植、沙箱化的执行环境
- **Proxy-Wasm ABI** - Envoy 代理扩展的标准接口
- **Protocol Buffers** - 高效的数据序列化
- **OpenTelemetry** - 遥测数据收集和导出

## 请求流程

下图说明了请求如何流经 SP-Istio Agent：

```
┌─────────────┐         ┌──────────────────────────────────┐         ┌─────────────┐
│             │         │       Envoy 代理 (Sidecar)      │         │             │
│   客户端    │────────▶│  ┌────────────────────────────┐  │────────▶│   上游服务   │
│             │         │  │   SP-Istio Agent (WASM)    │  │         │             │
│             │◀────────│  └────────────────────────────┘  │◀────────│             │
└─────────────┘         └──────────────────────────────────┘         └─────────────┘
                                       │
                                       │ 异步
                                       ▼
                               ┌───────────────┐
                               │   Softprobe   │
                               │    后端       │
                               └───────────────┘
```

### 详细流程

1.  **请求拦截**:
    -   Envoy 代理拦截传出的 HTTP 请求
    -   SP-Istio Agent WASM 插件接收请求头和请求体

2.  **代理查找**:
    -   插件检查是否有缓存的响应可用
    -   异步将请求元数据发送到 Softprobe 后端

3.  **缓存命中 (代理响应)**:
    -   如果存在缓存响应，则返回 HTTP 200 及缓存数据
    -   不调用原始上游服务
    -   显著减少延迟和负载

4.  **缓存未命中 (代理未命中)**:
    -   如果不存在缓存，则返回 HTTP 404
    -   请求正常继续流向上游服务
    -   对请求路径无影响

5.  **响应存储**:
    -   上游成功响应后，异步存储数据
    -   捕获响应头、响应体和计时信息
    -   发送到 Softprobe 进行分析和未来缓存

## 主要特性

### 异步处理

代理使用 **非阻塞、异步** 处理来最小化性能影响：

-   请求/响应捕获在后台进行
-   关键路径（请求转发）不被阻塞
-   与 Softprobe 的通信完全异步
-   最小的延迟开销（通常 < 1ms）

### 流式体处理

请求体和响应体以 **流式方式** 处理：

-   响应在数据块到达时即被转发（无缓冲）
-   无整体阻塞或内存累积
-   可配置的缓冲以满足分析需求
-   针对高流量场景的大小限制和采样

### 内存安全

使用 **Rust** 构建，保证内存安全：

-   无缓冲区溢出或内存泄漏
-   线程安全的并发处理
-   高效的资源利用
-   可预测的性能特征

### 沙箱化执行

在 **WebAssembly** 中运行提供隔离：

-   无法访问主机系统资源
-   仅限于 Proxy-Wasm ABI 的能力
-   与 Envoy 代理的故障隔离
-   无需重启代理即可轻松更新

## 数据捕获

### 请求数据

代理捕获：
- HTTP 方法、路径、查询参数
- 请求头
- 请求体（有大小限制）
- 客户端 IP 和元数据
- 计时信息

### 响应数据

代理捕获：
- HTTP 状态码
- 响应头
- 响应体（有大小限制）
- 上游服务信息
- 处理时间

### 业务上下文

代理通过以下信息丰富数据：
- 服务网格拓扑
- Kubernetes 元数据（命名空间、pod、标签）
- 追踪上下文（OpenTelemetry）
- 自定义业务标签

## 性能特征

### 延迟影响

-   **P50**: < 0.5ms 附加延迟
-   **P99**: < 2ms 附加延迟
-   **异步操作**: 对关键路径无影响

### 资源使用

-   **内存**: 每个 sidecar 约 10-20MB
-   **CPU**: 在典型工作负载中 < 5% 的开销
-   **网络**: 批量、压缩的数据传输

### 可扩展性

-   每个 pod 处理 **10,000+ 请求/秒**
-   随 pod 数量线性扩展
-   无集中式瓶颈
-   分布式架构

## 安全考虑

### 数据隐私

-   敏感数据可在捕获前被过滤
-   可配置的头/体内容编辑
-   PII 检测和掩码
-   符合数据法规

### 网络安全

-   与 Softprobe 的 TLS 加密通信
-   服务网格内的 mTLS 支持
-   无未加密数据传输
-   通过 API 密钥进行身份验证

### 访问控制

-   Kubernetes 资源的 RBAC 策略
-   命名空间级别的隔离
-   特定于工作负载的目标定位
-   审计日志

## 部署模式

### 全局模式

-   应用于网格中的所有工作负载
-   集中式配置
-   统一的数据捕获
-   部署在 `istio-system` 命名空间

### 范围模式

-   针对特定的命名空间或工作负载
-   细粒度的控制
-   逐步推出的能力
-   每个服务的配置

### 混合模式

-   结合全局和范围策略
-   每个工作负载可覆盖全局设置
-   灵活的部署策略
-   基于优先级的规则应用

## 集成点

### Istio 服务网格

-   使用 Istio 的 WasmPlugin CRD
-   利用 Envoy 的 WASM 运行时
-   与 Istio 遥测集成
-   与现有的 Istio 策略协同工作

### OpenTelemetry

-   导出追踪、指标、日志
-   与 OpenTelemetry Collector 兼容
-   支持分布式追踪
-   跨服务的上下文传播

### Kubernetes

-   使用 Kubernetes 元数据
-   与 RBAC 集成
-   尊重命名空间边界
-   与服务发现协同工作
