# 在 Trace 视图里读懂并处理差异

打开一次回放，点一个失败用例，你就进入 trace 视图：左边是调用树，选中某个 span 后，右边弹出 **diff 抽屉**，把录制响应（基准）和回放响应（本次）并排展示。本指南覆盖你在这里能做的一切。

如果你还没弄清 **修正判定** 和 **配置对比规则** 的区别，先看 [总览](/replay/overview#the-two-things-you-can-do-with-a-difference)——本页假设你已经理解它。

## 进入一处差异

1. 从回放列表打开一次**回放**。
2. 选一个**失败用例**。左侧面板按**失败 / 无效 / 通过**筛选——失败用例带红点列出。
3. **调用树**在右边出现：入口 span 加它的下游调用（数据库、HTTP 客户端等）。

<div className="sp-img">
  <img src="/img/docs/replay/trace-caselist.png" alt="失败用例列表和调用树" />
  <p className="sp-caption">第 1–3 步：失败用例列表（左，可筛选）和选中用例的调用树（右）。</p>
</div>

4. **点树里的一个 span**。**diff 抽屉**在右边打开，把录制响应和回放响应并排展示。

<div className="sp-img">
  <img src="/img/docs/replay/trace-diff-open.png" alt="diff 抽屉在调用树旁打开" />
  <p className="sp-caption">第 4 步：点 span 打开 diff 抽屉——录制响应（基准）在左，回放响应（本次）在右。</p>
</div>

从这里你读 diff、决定每处差异怎么处理。本指南余下部分覆盖每个动作。


## 读 diff

选中每个 span 都会打开一个两栏 diff：

- **左 — 录制响应（基准）**：录制时采集到的内容。
- **右 — 回放响应（本次）**：回放时服务返回的内容。

右栏头部汇总本次对比：

- **`N 处差异`**——值不同且仍计为差异的字段。点它旁边的 **↑ / ↓** 可以逐处跳转。
- **`N 处已忽略`**——有差异但命中了忽略规则、因而不计入的字段。点它会打开一个小面板，列出每个被忽略字段以及挡下它的规则。见 [查看已忽略的内容](#reviewing-whats-ignored)。

被忽略的字段在**两栏都会画上删除线**——录制侧和回放侧——用灰色删除线。两侧都划，是为了清楚表明这个字段完全退出了对比，而不只是某一侧。悬停删除线会显示 **「已被规则忽略：`{规则名}`」**。

:::note 整类忽略的调用
如果整个下游依赖类型被忽略（例如通过 [依赖类型整类忽略](/replay/compare-rules#ignore-categories-by-dependency-type) 忽略了所有 Redis 或所有 Database 调用），抽屉会显示一个灰色 chip **「本类已整类忽略」**，而不是逐字段删除线。整类忽略是整体挡下的，所以没有单个字段差异可划线。
:::

## 忽略一个字段 {#ignoring-a-field}

你在 diff 内部忽略某个字段的差异。打开忽略菜单有两种方式：

1. **悬停差异行。** gutter 里会出现一个 **eye-off 图标**，点它。
2. **右键该行**，或点右栏顶部的 **忽略规则** 按钮（它作用于你光标所在的行——如果你还没点过任何字段行，它会提示 *「先在 diff 里点击要忽略的字段行」*）。

菜单顶部显示字段路径，下面是两个忽略动作：

- **忽略此字段的差异**——只忽略这一个精确路径（例如 `/data/downstreamToken`）。
- **忽略所有 "`{name}`" 字段**——忽略响应里任何位置、叶子名叫这个的所有字段（可能有多处）。

<div className="sp-img">
  <img src="/img/docs/replay/ignore-menu.png" alt="带 scope 子菜单的忽略菜单" />
  <p className="sp-caption">忽略菜单，scope 子菜单分成「立即生效」（仅此用例）和「比对规则 · 下次回放生效」（仅此接口 / 所有接口）两组。</p>
</div>


每个动作都会展开一个 **scope 子菜单**，分成两组，把忽略何时生效讲清楚：

| 分组 | 作用范围 | 做什么 |
| --- | --- | --- |
| **立即生效** | **仅此用例** | 立即修正这一条用例的判定。下次回放这条用例时失效。不改动配置。 |
| **比对规则 · 下次回放生效** | **仅此接口** | 写一条作用于此接口的规则。下次回放生效。 |
| | **所有接口** | 写一条作用于整个应用的规则。下次回放生效。 |

### 选了 scope 之后发生什么

- **仅此用例**——字段立即在这条用例上被接受：画删除线、差异数下降、用例状态和回放通过率更新。toast 确认 *「已忽略字段 `{path}`（仅此用例）」*，并带一个 8 秒的 **撤销** 动作。
- **仅此接口 / 所有接口**——规则写进你的配置，但**当前这次回放不变**——字段在这里*不*画删除线，因为规则下次回放才生效。toast 确认 *「已添加规则：忽略 `{path}`（`{scope}`）· 下次回放生效」*，并带一个 **立即重新比对** 动作。点它（或头部按钮）把规则应用到本次回放——见 [重新比对](#recompare-apply-rules-to-an-existing-run)。

<div className="sp-img">
  <img src="/img/docs/replay/rule-added-toast.png" alt="已添加规则 toast 和头部的重新比对按钮" />
  <p className="sp-caption">接口/应用档忽略后：toast 确认规则下次回放生效（带「立即重新比对」快捷入口），回放通过率不变，头部出现「规则已变更 · 重新比对」按钮。</p>
</div>

:::tip 接口/应用档忽略为什么不改变你正在看的内容
这是有意的。对比规则是给*下次*回放用的配置，所以它不动当前这次回放、保持自洽。要看它对当前回放的效果，就重新比对。
:::

## 标记整个用例通过

有时用例的差异是真的，但可以接受——一次故意的行为变更，或一次 SoftProbe 采集造成的假差异。与其逐字段忽略，你可以接受**整条用例**。

在失败用例上，点 **标记通过**。一个小表单会问：

- **原因**（必填，二选一）：
  - **差异符合预期（设计如此）**——变更是故意的。
  - **SoftProbe 采集/对比问题**——差异是工具造成的，不是真实变更。
- **备注**（可选）——自由文本，留档以备查。

确认后，用例从失败桶移入通过桶，通过率立即更新。这是单用例的判定（不写任何规则，也不影响其他用例），原因和备注会存下来供日后查看。

## 重新比对——把规则应用到一次已有的回放 {#recompare-apply-rules-to-an-existing-run}

一次回放的结果在回放跑完时就算好并存了。接口和应用对比规则**下次**回放才生效——它们不会追溯地改变一次已跑完的回放。**重新比对** 弥补这个落差：它按**当前**规则重新判定这次回放已存的响应，并重写回放统计。它**不**重放任何流量。

当你从 diff 里加了或删了一条接口/应用规则，run 头部会出现一个 **重新比对** 控件。它有四种状态：

| 状态 | 外观 | 含义 |
| --- | --- | --- |
| 规则已变更 | **规则已变更 · 重新比对**（可点） | 你改了规则；点它应用到本次回放。 |
| 进行中 | **重新比对中 `{done}` / `{total}`**（旋转） | 正在重判回放的行。 |
| 完成 | **重新比对完成：`{passed}` 转通过，`{failed}` 转失败** | 已完成；列表、计数、通过率已同步。 |
| 失败 | **重新比对失败，点击重试** | 出错了；悬停看详情，点它重试。 |

没有需要重新比对的东西时，控件隐藏——你只是看结果时它绝不打扰你。

点它会按当前规则重判回放里每一个非异常行，然后重写每个接口的通过/失败计数。完成时，用例列表、计数、通过率一起更新，你打开的任何 diff 抽屉也会重画删除线以匹配。

<div className="sp-img">
  <img src="/img/docs/replay/recompare-done.png" alt="头部的重新比对完成态" />
  <p className="sp-caption">重新比对完成时，头部显示有多少用例转通过或转失败，通过率随之更新。</p>
</div>


:::info 「立即重新比对」快捷入口
每条「已添加/已删除规则」的 toast 都带一个 **立即重新比对** 动作——同一操作的快捷入口，让你不必去找头部按钮就能立刻应用规则。
:::

## 取消忽略

要恢复某个你之前忽略字段的对比，右键它的删除线行，选 **取消忽略（恢复比对）**——挡下它的规则名会作为副标题显示。

你不需要记得这个字段当初是怎么被忽略的。SoftProbe 先试最窄的范围，再自动放宽：

1. **此用例**——如果字段是在这条用例上被修正的，那个标记会被移除，差异立即回来。
2. **规则**——否则删掉挡下它的那条快捷规则（先按路径，再按字段名）。删的是最窄的匹配规则（接口优先于应用），toast 告诉你影响了哪个范围：*「已删除规则：`{target}`（`{scope}`）· 下次回放生效」*，同样带一个 **立即重新比对** 动作。

如果找不到快捷规则（可能已在别处删除，或它配在全局默认策略里），SoftProbe 会明确告诉你，并指引你去 **[对比规则](/replay/compare-rules)** 页处理——它绝不会让你卡在一条清不掉的删除线上反复点。

:::note 取消忽略会删掉原来的规则
取消忽略会移除当初创建它的那条规则——不会在上面叠加一条反向规则。这让你的配置保持干净、可逆。
:::

## 查看已忽略的内容 {#reviewing-whats-ignored}

你不必逐个打开 span 才能知道一条用例上忽略了什么。只要用例有任何被忽略字段，trace 头部就会显示一个 **「N 处已忽略」** chip。点它打开一个标题为 **「本用例已忽略 N 处」** 的汇总面板，按调用分组列出每个被忽略字段：

- 字段 **路径**，
- 挡下它的**规则**——对单用例判定修正显示为 **「仅此用例」**，对配置的规则显示规则名（兜底为「对比规则」）。

<div className="sp-img">
  <img src="/img/docs/replay/ignored-summary.png" alt="case 级忽略总览面板" />
  <p className="sp-caption">忽略总览面板：这条 case 上每个被忽略字段，按调用分组，带挡下它的规则和逐行「取消忽略」动作。</p>
</div>


悬停任一行会出现 **取消忽略** 动作，让你直接从汇总里把字段恢复对比——无需打开它所在 span 的 diff。因为那个 span 的抽屉通常是关着的，从这里取消会就地重算那一行，让汇总保持准确。

## 速查——所有动作

| 动作 | 位置 | 改变什么 | 何时生效 |
| --- | --- | --- | --- |
| 忽略此字段的差异 → 仅此用例 | diff 行菜单 | 这条用例的判定 | 立即（重放后失效） |
| 忽略此字段的差异 → 仅此接口 / 所有接口 | diff 行菜单 | 一条对比规则 | 下次回放（或重新比对） |
| 忽略所有 "`{name}`" 字段 → *（任一 scope）* | diff 行菜单 | 同上，作用于每个同名字段 | 同上 |
| 标记通过 | 用例头部（失败用例） | 整条用例的判定 | 立即 |
| 重新比对 | run 头部 | 按当前规则重判本次回放 | 立即（不重放） |
| 取消忽略 | 删除线行 / 汇总面板 | 移除用例标记或规则 | 立即（用例）/ 下次回放（规则） |
