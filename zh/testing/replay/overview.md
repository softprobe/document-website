# 回放对比总览

回放录制的流量时，Softprobe 会把每个响应和录制时的内容逐字段对比。任何不一致的字段就是一处**差异**；有差异的用例被判为**失败**。

大多数差异不是真 bug。时间戳、随机 token、ID 每次调用都在变——它们永远会「不一样」，但并没有出错。你要做的，是告诉 Softprobe 忽略哪些差异。有两种做法，选对哪一种是关键。

## 改这一次的判定，还是配一条规则 {#fix-a-verdict-or-write-a-rule}

假设一个字段有差异，但你看过后觉得没问题。你可以用两种方式接受它：

- **改判定** —— *「这一次回放里，这条差异其实是对的。」* 立即生效，且只影响这一次回放。用于：你人工看过某条用例，确认它不是真 bug。
- **配对比规则** —— *「以后每次回放，都别比这个字段。」* 永久生效，影响所有未来回放。用于：某字段天生每次都不同（时间戳、随机 ID），本就不该参与比对。

一句话选：**只想改这一次的结果 → 改判定；想一劳永逸 → 配规则。**

| | 改判定 | 配对比规则 |
| --- | --- | --- |
| **作用范围** | 只这一次回放 | 以后每一次回放 |
| **持续多久** | 一次性——下次回放就没了 | 永久——存在配置里 |
| **用于** | 你已经看过并接受的一条用例 | 一个总在变的字段 |
| **在哪操作** | 读回放时，对着那处差异 | 读回放时，或在对比规则页 |

::: tip 两者配合使用
一条对比规则不会动已经跑完的回放——它只在下次回放时才起作用。如果你配了一条规则、又想看它对你正在看的这次回放有什么影响，用 **[重新比对](/zh/testing/replay/handle-failed-run#recompare-apply-rules-to-an-existing-run)**：它按你最新的规则重新检查当前回放，不重放任何流量。
:::
